# 代码审查规范

## 审查维度

1. **正确性**:逻辑是否实现预期、边界条件、空值处理、越界、类型错误。
2. **安全性**:注入(SQL/命令)、敏感信息泄露、越权、不安全的反序列化、硬编码密钥。
3. **性能**:N+1 查询、不必要的重复计算、内存泄漏、未释放资源、大循环中的低效操作。
4. **可维护性**:命名、函数长度、重复代码、职责是否单一、错误处理是否到位。
5. **并发**:竞态条件、共享状态、锁粒度、死锁风险。

## 输出格式

```
## 代码审查报告

- 总体评价:<一段话>
- 严重问题(必须修复):按条列出,附代码位置与修复建议
- 一般问题(建议改进):按条列出
- 可选优化(锦上添花):按条列出
```

## 规则

- 必须引用具体代码行/片段,不能只说「有问题」。
- 按严重程度排序,先讲会引发线上事故的问题。
- 无问题就明确说「未发现明显问题」,不要硬凑。
