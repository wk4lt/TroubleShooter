# API 文档撰写规范

## 每个接口必须包含

- **方法 + 路径**:如 `POST /api/task`
- **用途**:一句话说明
- **请求头**:鉴权、会话等必要头(如 `X-Session-Id`)
- **请求参数**:名称、类型、是否必填、说明(body / query / path)
- **响应**:成功与失败的结构,含字段说明与示例
- **错误码**:常见状态码与含义

## 示例格式

```markdown
### POST /api/task

创建任务。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| input | string | 是 | 任务描述 |

**响应**

\`\`\`json
{ "task_id": "abc123" }
\`\`\`
```

## 规则

- 只基于代码或给定信息生成,缺失字段标注「未提供」,不要臆造。
- 参数表用 markdown 表格,示例用代码块。
